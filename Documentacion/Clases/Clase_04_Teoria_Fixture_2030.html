📄Introducción a MongoDB

¿Qué es MongoDB?

MongoDB es una base de datos NoSQL orientada a documentos que almacena datos en formato BSON (Binary JSON). Es una de las bases de datos NoSQL más populares del mundo, utilizada por empresas como Facebook, Google, Adobe, y Uber.

🔄 Esquema Flexible

Los documentos en una colección pueden tener estructuras diferentes. Ideal para datos semi-estructurados y evolución de esquemas.

📈 Escalabilidad Horizontal

Sharding nativo para distribuir datos entre múltiples servidores. Escalamiento automático y transparente.

🔍 Consultas Ricas

Soporte para consultas complejas, índices secundarios, búsquedas de texto completo y geoespaciales.

⚡ Alto Rendimiento

Optimizado para lecturas y escrituras rápidas. Soporte para índices compuestos y pipeline de agregación.

🛡️ Alta Disponibilidad

Replica sets con failover automático. Garantiza disponibilidad incluso con fallos de nodos.

🔧 Facilidad de Desarrollo

Mapeo natural con objetos de programación. Drivers oficiales para todos los lenguajes principales.

Casos de Uso Ideales

📱 Aplicaciones Web y Móviles

Perfiles de usuario, configuraciones, contenido dinámico. La flexibilidad del esquema permite evolución rápida.

📊 Gestión de Contenido

CMS, blogs, catálogos de productos. Documentos complejos con estructuras anidadas.

🌐 APIs y Microservicios

Almacenamiento de datos JSON nativos. Integración directa con aplicaciones REST.

📈 Analytics en Tiempo Real

Eventos, logs, métricas. Pipeline de agregación para análisis complejos.

Cuándo NO usar MongoDB

⚠️ Limitaciones Importantes

  • Transacciones ACID complejas: Aunque MongoDB 4.0+ soporta transacciones multi-documento, no es tan robusto como bases relacionales
  • Consultas relacionales complejas: JOINs son limitados, mejor usar $lookup con cuidado
  • Datos altamente normalizados: Si tu modelo es muy relacional, SQL puede ser mejor opción
  • Reportes complejos: Para BI y reportes complejos, considera data warehouses especializados

🏗️Arquitectura y Conceptos Clave

Jerarquía de Datos

MongoDB Server ├── Database (Base de Datos) │ ├── Collection (Colección) ≈ Tabla en SQL │ │ ├── Document (Documento) ≈ Fila en SQL │ │ │ ├── Field (Campo) ≈ Columna en SQL │ │ │ └── Value (Valor) │ │ └── Document │ └── Collection └── Database

Comparación con Bases Relacionales

Concepto SQL Concepto MongoDB Descripción
Database Database Contenedor de alto nivel para datos
Table Collection Grupo de registros relacionados
Row Document Registro individual de datos
Column Field Atributo específico del registro
Primary Key _id Identificador único (ObjectId)
JOIN $lookup / Embedding Relacionar datos entre colecciones

Tipos de Datos BSON

📝 String

Texto UTF-8. Más eficiente que JSON para strings largos.

🔢 Number

Int32, Int64, Double, Decimal128 para precisión financiera.

📅 Date

Timestamps con precisión de milisegundos.

🆔 ObjectId

Identificador único de 12 bytes con timestamp embebido.

📋 Array

Listas ordenadas de valores de cualquier tipo.

📦 Object

Documentos anidados (subdocumentos).

✅ Boolean

Valores true/false.

🗂️ Binary

Datos binarios como imágenes o archivos.

📋Diseño de Esquemas

Principios Fundamentales

A diferencia de las bases relacionales, MongoDB no impone un esquema fijo, pero esto no significa que no debas diseñar cuidadosamente la estructura de tus documentos.

🎯 Diseña para tu aplicación

Estructura los documentos según cómo tu aplicación accede a los datos, no según la normalización relacional.

📊 Considera los patrones de consulta

Optimiza para las consultas más frecuentes. Desnormaliza si es necesario para mejorar performance.

📏 Límites de documentos

Máximo 16MB por documento. Diseña pensando en el crecimiento de datos.

🔄 Evolución del esquema

Planifica cómo evolucionará tu esquema. MongoDB permite cambios graduales.

Embedding vs Referencing

📦 Embedding (Documentos Anidados)

Cuándo usar: Relación 1:1 o 1:pocos, datos que se consultan juntos

// Ejemplo: Blog post con comentarios { "_id": ObjectId("..."), "titulo": "Introducción a MongoDB", "contenido": "MongoDB es una base de datos...", "autor": "María García", "fechaPublicacion": ISODate("2024-01-15"), "comentarios": [ { "autor": "Juan López", "texto": "Excelente artículo!", "fecha": ISODate("2024-01-16") }, { "autor": "Ana Martín", "texto": "Muy útil, gracias", "fecha": ISODate("2024-01-17") } ], "tags": ["mongodb", "nosql", "tutorial"] }

Ventajas: Una sola consulta, atomicidad, mejor performance para lecturas

Desventajas: Documentos grandes, duplicación de datos, límite de 16MB

🔗 Referencing (Referencias)

Cuándo usar: Relación 1:muchos o muchos:muchos, datos que crecen indefinidamente

// Colección: usuarios { "_id": ObjectId("507f1f77bcf86cd799439011"), "nombre": "Juan Pérez", "email": "juan@email.com" } // Colección: pedidos { "_id": ObjectId("507f1f77bcf86cd799439012"), "usuarioId": ObjectId("507f1f77bcf86cd799439011"), "productos": [ { "productoId": ObjectId("507f1f77bcf86cd799439013"), "cantidad": 2, "precio": 25.99 } ], "total": 51.98, "fecha": ISODate("2024-01-15") } // Consulta con $lookup (JOIN) db.pedidos.aggregate([ { $lookup: { from: "usuarios", localField: "usuarioId", foreignField: "_id", as: "usuario" } } ])

Ventajas: Documentos más pequeños, menos duplicación, escalabilidad

Desventajas: Múltiples consultas, no hay integridad referencial automática

Patrones de Diseño Comunes

🌳 Tree Pattern

Para estructuras jerárquicas como categorías o comentarios anidados.

{ "_id": ObjectId("..."), "nombre": "Electrónicos", "padre": null, "ancestros": [], "hijos": ["Smartphones", "Laptops"] }
📊 Bucket Pattern

Para series temporales, agrupando datos por tiempo.

{ "_id": ObjectId("..."), "sensor": "temp_01", "fecha": ISODate("2024-01-15"), "mediciones": [ { "hora": "00:00", "valor": 22.5 }, { "hora": "01:00", "valor": 21.8 } ] }
🔄 Polymorphic Pattern

Para documentos con estructuras similares pero diferentes.

// Producto físico { "tipo": "fisico", "nombre": "Laptop", "peso": 2.5, "dimensiones": "30x20x2cm" } // Producto digital { "tipo": "digital", "nombre": "Software", "tamanoArchivo": "150MB", "licencia": "MIT" }

🔧Operaciones CRUD

Operaciones Básicas

CREATE

Insertar documentos

insertOne(), insertMany()

READ

Consultar documentos

find(), findOne()

UPDATE

Modificar documentos

updateOne(), updateMany()

DELETE

Eliminar documentos

deleteOne(), deleteMany()

CREATE - Inserción de Documentos

// Insertar un documento db.usuarios.insertOne({ nombre: "Ana García", email: "ana@email.com", edad: 25, fechaRegistro: new Date(), activo: true }); // Insertar múltiples documentos db.usuarios.insertMany([ { nombre: "Carlos López", email: "carlos@email.com", edad: 30 }, { nombre: "María Rodríguez", email: "maria@email.com", edad: 28 } ]); // Inserción con _id personalizado db.productos.insertOne({ _id: "PROD-001", nombre: "Laptop Gaming", precio: 1299.99, categoria: "Electrónicos" });

READ - Consultas

// Buscar todos los documentos db.usuarios.find(); // Buscar con filtro db.usuarios.find({ edad: { $gte: 25 } }); // Buscar uno específico db.usuarios.findOne({ email: "ana@email.com" }); // Proyección (seleccionar campos específicos) db.usuarios.find( { activo: true }, { nombre: 1, email: 1, _id: 0 } ); // Ordenamiento y límite db.usuarios.find() .sort({ fechaRegistro: -1 }) .limit(10); // Consultas complejas db.productos.find({ $and: [ { precio: { $gte: 100, $lte: 1000 } }, { categoria: "Electrónicos" }, { stock: { $gt: 0 } } ] }); // Búsqueda en arrays db.usuarios.find({ intereses: "tecnología" }); // Búsqueda en documentos anidados db.usuarios.find({ "direccion.ciudad": "Buenos Aires" }); // Expresiones regulares db.usuarios.find({ nombre: /^Ana/ });

UPDATE - Modificaciones

// Actualizar un documento db.usuarios.updateOne( { email: "ana@email.com" }, { $set: { edad: 26, ultimaActividad: new Date() } } ); // Actualizar múltiples documentos db.usuarios.updateMany( { activo: false }, { $set: { fechaBaja: new Date() } } ); // Operadores de actualización db.usuarios.updateOne( { _id: ObjectId("...") }, { $set: { nombre: "Ana García López" }, $inc: { puntos: 10 }, $push: { intereses: "fotografía" }, $addToSet: { tags: "premium" }, $unset: { campoTemporal: "" } } ); // Upsert (insertar si no existe) db.configuracion.updateOne( { clave: "tema" }, { $set: { valor: "oscuro" } }, { upsert: true } ); // Actualización con pipeline de agregación db.productos.updateMany( {}, [ { $set: { precioConDescuento: { $multiply: ["$precio", 0.9] } } } ] );

DELETE - Eliminación

// Eliminar un documento db.usuarios.deleteOne({ email: "usuario@eliminar.com" }); // Eliminar múltiples documentos db.usuarios.deleteMany({ activo: false }); // Eliminar todos los documentos de una colección db.logs.deleteMany({}); // Eliminar colección completa db.temporal.drop(); // Soft delete (marcado como eliminado) db.usuarios.updateOne( { _id: ObjectId("...") }, { $set: { eliminado: true, fechaEliminacion: new Date() } } );

Operaciones Avanzadas

// Transacciones (MongoDB 4.0+) const session = db.getMongo().startSession(); session.startTransaction(); try { db.cuentas.updateOne( { _id: "cuenta_a" }, { $inc: { saldo: -100 } }, { session } ); db.cuentas.updateOne( { _id: "cuenta_b" }, { $inc: { saldo: 100 } }, { session } ); session.commitTransaction(); } catch (error) { session.abortTransaction(); throw error; } finally { session.endSession(); } // Bulk operations const bulk = db.productos.initializeUnorderedBulkOp(); bulk.insert({ nombre: "Producto 1", precio: 10 }); bulk.find({ precio: { $lt: 5 } }).update({ $inc: { precio: 1 } }); bulk.find({ stock: 0 }).remove(); bulk.execute();

⚡Indexación y Performance

Importancia de los Índices

Los índices son estructuras de datos que mejoran la velocidad de las consultas. Sin índices, MongoDB debe examinar cada documento (collection scan), lo que es ineficiente para colecciones grandes.

📊 Impacto en Performance

  • Sin índice: O(n) - examina todos los documentos
  • Con índice: O(log n) - búsqueda logarítmica
  • Ejemplo: En 1 millón de documentos, sin índice = 1M operaciones, con índice = ~20 operaciones

Tipos de Índices

🔍 Single Field

Índice en un solo campo. El más básico y común.

db.usuarios.createIndex({ email: 1 })
📊 Compound

Índice en múltiples campos. Orden importa.

db.productos.createIndex({ categoria: 1, precio: -1 })
📝 Text

Búsqueda de texto completo en strings.

db.articulos.createIndex({ titulo: "text", contenido: "text" })
🌍 Geospatial

Para consultas geográficas y de proximidad.

db.lugares.createIndex({ ubicacion: "2dsphere" })
🔢 Partial

Índice solo en documentos que cumplen condición.

db.usuarios.createIndex( { email: 1 }, { partialFilterExpression: { activo: true } } )
⏰ TTL

Elimina documentos automáticamente después de tiempo.

db.sesiones.createIndex( { fechaCreacion: 1 }, { expireAfterSeconds: 3600 } )

Gestión de Índices

// Crear índices db.usuarios.createIndex({ email: 1 }, { unique: true }); db.productos.createIndex({ nombre: 1, categoria: 1 }); // Listar índices db.usuarios.getIndexes(); // Información sobre uso de índices db.usuarios.find({ email: "ana@email.com" }).explain("executionStats"); // Eliminar índice db.usuarios.dropIndex({ email: 1 }); db.usuarios.dropIndex("email_1"); // Reindexar colección db.usuarios.reIndex(); // Índice en background (no bloquea escrituras) db.productos.createIndex( { descripcion: "text" }, { background: true } ); // Índice sparse (solo documentos con el campo) db.usuarios.createIndex( { telefono: 1 }, { sparse: true } );

Optimización de Consultas

// Analizar plan de ejecución db.usuarios.find({ edad: { $gte: 25 } }).explain("executionStats"); // Resultado del explain: { "executionStats": { "totalExamined": 1000, // Documentos examinados "totalDocsReturned": 250, // Documentos devueltos "executionTimeMillis": 45, // Tiempo de ejecución "indexesUsed": ["edad_1"] // Índices utilizados } } // Hint para forzar uso de índice específico db.productos.find({ categoria: "Electrónicos" }) .hint({ categoria: 1, precio: -1 }); // Profiling para identificar consultas lentas db.setProfilingLevel(2, { slowms: 100 }); db.system.profile.find().sort({ ts: -1 }).limit(5);

Mejores Prácticas

🎯 Índices Selectivos

Crea índices en campos que se usan frecuentemente en consultas y que tienen alta cardinalidad.

📏 Orden en Índices Compuestos

Coloca campos de igualdad primero, luego rangos, finalmente ordenamiento.

⚖️ Balance Lectura/Escritura

Más índices = lecturas más rápidas pero escrituras más lentas. Encuentra el equilibrio.

📊 Monitoreo Continuo

Usa explain() regularmente y monitorea métricas de performance en producción.

📊Pipeline de Agregación

¿Qué es el Pipeline de Agregación?

El pipeline de agregación es un framework para transformar y analizar datos. Permite realizar operaciones complejas como agrupaciones, cálculos, filtros y transformaciones en múltiples etapas.

// Estructura básica del pipeline db.coleccion.aggregate([ { $match: { /* filtros */ } }, { $group: { /* agrupación */ } }, { $sort: { /* ordenamiento */ } }, { $project: { /* proyección */ } } ]);

Etapas Principales

🔍 $match

Filtra documentos (equivalente a WHERE en SQL)

{ $match: { edad: { $gte: 18 }, activo: true } }
📊 $group

Agrupa documentos y calcula valores (GROUP BY)

{ $group: { _id: "$categoria", total: { $sum: "$precio" }, promedio: { $avg: "$precio" }, count: { $sum: 1 } } }
📋 $project

Selecciona y transforma campos (SELECT)

{ $project: { nombre: 1, precioConIVA: { $multiply: ["$precio", 1.21] }, _id: 0 } }
🔄 $sort

Ordena documentos (ORDER BY)

{ $sort: { fecha: -1, precio: 1 } }
📏 $limit / $skip

Paginación de resultados

{ $skip: 20 }, { $limit: 10 }
🔗 $lookup

JOIN entre colecciones

{ $lookup: { from: "usuarios", localField: "usuarioId", foreignField: "_id", as: "usuario" } }

Ejemplos Prácticos

📈 Análisis de Ventas por Categoría
db.ventas.aggregate([ // Filtrar ventas del último mes { $match: { fecha: { $gte: new Date("2024-01-01"), $lt: new Date("2024-02-01") } } }, // Agrupar por categoría { $group: { _id: "$categoria", totalVentas: { $sum: "$monto" }, cantidadVentas: { $sum: 1 }, promedioVenta: { $avg: "$monto" }, maxVenta: { $max: "$monto" }, minVenta: { $min: "$monto" } } }, // Ordenar por total de ventas { $sort: { totalVentas: -1 } }, // Formatear resultado { $project: { categoria: "$_id", totalVentas: { $round: ["$totalVentas", 2] }, cantidadVentas: 1, promedioVenta: { $round: ["$promedioVenta", 2] }, _id: 0 } } ]);
👥 Top 10 Usuarios Más Activos
db.actividades.aggregate([ // Agrupar por usuario { $group: { _id: "$usuarioId", totalActividades: { $sum: 1 }, ultimaActividad: { $max: "$fecha" }, tiposActividad: { $addToSet: "$tipo" } } }, // JOIN con colección usuarios { $lookup: { from: "usuarios", localField: "_id", foreignField: "_id", as: "usuario" } }, // Descomponer array de usuario { $unwind: "$usuario" }, // Proyectar campos necesarios { $project: { nombre: "$usuario.nombre", email: "$usuario.email", totalActividades: 1, ultimaActividad: 1, cantidadTipos: { $size: "$tiposActividad" }, _id: 0 } }, // Ordenar por actividades { $sort: { totalActividades: -1 } }, // Top 10 { $limit: 10 } ]);
📊 Análisis Temporal de Registros
db.usuarios.aggregate([ // Agregar campos de fecha { $addFields: { año: { $year: "$fechaRegistro" }, mes: { $month: "$fechaRegistro" }, diaSemana: { $dayOfWeek: "$fechaRegistro" } } }, // Agrupar por año y mes { $group: { _id: { año: "$año", mes: "$mes" }, registros: { $sum: 1 }, usuariosActivos: { $sum: { $cond: [{ $eq: ["$activo", true] }, 1, 0] } } } }, // Calcular porcentaje de activos { $addFields: { porcentajeActivos: { $multiply: [ { $divide: ["$usuariosActivos", "$registros"] }, 100 ] } } }, // Ordenar por fecha { $sort: { "_id.año": 1, "_id.mes": 1 } } ]);

Operadores Avanzados

// Operadores de array { $project: { nombre: 1, cantidadIntereses: { $size: "$intereses" }, primerInteres: { $arrayElemAt: ["$intereses", 0] }, tieneDeportes: { $in: ["deportes", "$intereses"] } } } // Operadores condicionales { $project: { nombre: 1, categoria: { $switch: { branches: [ { case: { $lt: ["$edad", 18] }, then: "Menor" }, { case: { $lt: ["$edad", 65] }, then: "Adulto" }, { case: { $gte: ["$edad", 65] }, then: "Senior" } ], default: "Desconocido" } } } } // Operadores de fecha { $project: { nombre: 1, añoRegistro: { $year: "$fechaRegistro" }, mesRegistro: { $month: "$fechaRegistro" }, diasDesdeRegistro: { $divide: [ { $subtract: [new Date(), "$fechaRegistro"] }, 1000 * 60 * 60 * 24 ] } } }

🔄Replicación y Sharding

Replica Sets

Un Replica Set es un grupo de instancias MongoDB que mantienen el mismo conjunto de datos. Proporciona redundancia y alta disponibilidad.

👑 Primary

Nodo principal que recibe todas las escrituras. Solo puede haber uno.

📚 Secondary

Nodos que replican datos del Primary. Pueden servir lecturas.

🗳️ Arbiter

Nodo que solo vota en elecciones, no almacena datos.

Configuración de Replica Set

# Docker Compose para Replica Set version: '3.8' services: mongo1: image: mongo:7.0 command: mongod --replSet rs0 --port 27017 ports: - "27017:27017" volumes: - mongo1_data:/data/db mongo2: image: mongo:7.0 command: mongod --replSet rs0 --port 27018 ports: - "27018:27018" volumes: - mongo2_data:/data/db mongo3: image: mongo:7.0 command: mongod --replSet rs0 --port 27019 ports: - "27019:27019" volumes: - mongo3_data:/data/db volumes: mongo1_data: mongo2_data: mongo3_data:
// Inicializar Replica Set rs.initiate({ _id: "rs0", members: [ { _id: 0, host: "localhost:27017", priority: 2 }, { _id: 1, host: "localhost:27018", priority: 1 }, { _id: 2, host: "localhost:27019", priority: 1 } ] }); // Verificar estado rs.status(); // Configurar read preference db.usuarios.find().readPref("secondary"); // Write concern para replica set db.usuarios.insertOne( { nombre: "Test" }, { writeConcern: { w: "majority", j: true } } );

Sharding (Particionamiento Horizontal)

Sharding distribuye datos entre múltiples máquinas. MongoDB soporta sharding automático basado en una shard key.

// Habilitar sharding en base de datos sh.enableSharding("tienda"); // Crear índice en shard key db.productos.createIndex({ categoria: 1, _id: 1 }); // Configurar sharding en colección sh.shardCollection("tienda.productos", { categoria: 1, _id: 1 }); // Ver distribución de chunks sh.status(); // Balanceador automático sh.getBalancerState(); sh.setBalancerState(true);

Estrategias de Shard Key

🎯 Alta Cardinalidad

Muchos valores únicos para distribución uniforme. Evita hotspots.

📊 Baja Frecuencia

Valores que no cambian frecuentemente. Evita migraciones constantes.

🔄 No Monótona

Evita valores que siempre crecen (timestamps, ObjectIds). Causa hotspots.

🎪 Consultas Dirigidas

Incluye la shard key en consultas frecuentes para evitar broadcast.

⚠️ Consideraciones Importantes

  • Shard key inmutable: No se puede cambiar después de sharding
  • Límite de documento: 16MB por documento en todos los shards
  • Transacciones: Limitadas dentro del mismo shard en versiones anteriores
  • Complejidad operacional: Requiere más monitoreo y mantenimiento
