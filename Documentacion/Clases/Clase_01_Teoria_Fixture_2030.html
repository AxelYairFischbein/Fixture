Modelo Relacional vs Estructuras No Relacionales

📖Introducción

En la era del Big Data y las aplicaciones web modernas, las bases de datos relacionales tradicionales enfrentan desafíos significativos. El crecimiento exponencial de datos, la necesidad de escalabilidad horizontal, y la diversidad de tipos de datos han dado lugar a un nuevo paradigma: NoSQL.

¿Por qué surge NoSQL?

  • Escalabilidad: Necesidad de manejar petabytes de datos
  • Flexibilidad: Esquemas dinámicos para datos semiestructurados
  • Performance: Optimización para casos de uso específicos
  • Distribución: Arquitecturas distribuidas y en la nube

💡Concepto de NoSQL

Definición

NoSQL originalmente significaba "No SQL", pero ha evolucionado para representar "Not Only SQL". Se refiere a una amplia clase de sistemas de gestión de bases de datos que difieren del modelo relacional clásico.

Características Fundamentales

🔄 Esquema Flexible

No requieren un esquema fijo predefinido. Los datos pueden tener estructuras variables dentro de la misma colección.

📈 Escalabilidad Horizontal

Diseñadas para distribuir datos a través de múltiples servidores (sharding) de manera eficiente.

⚡ Alto Rendimiento

Optimizadas para operaciones específicas: lecturas rápidas, escrituras masivas, consultas complejas.

🌐 Distribución Geográfica

Soporte nativo para replicación y distribución de datos a nivel global.

Tipos Principales de NoSQL

1. Documentales (MongoDB, CouchDB) - Almacenan documentos JSON/BSON - Ideales para contenido web, catálogos 2. Clave-Valor (Redis, DynamoDB) - Estructura más simple: clave → valor - Perfectas para cache, sesiones 3. Grafos (Neo4j, ArangoDB) - Modelan relaciones complejas - Redes sociales, recomendaciones 4. Columnares/Tabular (Cassandra, HBase) - Optimizadas para análisis - Big Data, series temporales 5. Objetos (IRIS, db4o) - Mapean objetos directamente - Aplicaciones complejas, CAD/CAM 6. Multidimensional/Arrays (InfluxDB, Apache Druid) - Optimizadas para series temporales, OLAP - IoT, análisis de datos, finanzas

⚖️Relacional vs NoSQL

Aspecto Bases de Datos Relacionales Bases de Datos NoSQL
Esquema Fijo, predefinido (DDL) Flexible, dinámico
Escalabilidad Vertical (más potencia) Horizontal (más servidores)
Transacciones ACID completo BASE (eventual consistency)
Consultas SQL estándar APIs específicas, algunos SQL-like
Relaciones JOINs nativos Desnormalización, referencias
Consistencia Inmediata (strong consistency) Eventual (configurable)
Casos de Uso Sistemas transaccionales, ERP Big Data, aplicaciones web, IoT

💡 Punto Clave

No es una cuestión de "mejor" o "peor", sino de herramienta adecuada para el problema específico. Muchas organizaciones utilizan ambos tipos en arquitecturas políglota.

📊Relación con Volúmenes de Datos

Las 5 V's del Big Data

📏 Volumen

Terabytes → Petabytes
NoSQL maneja escalas masivas que superan las capacidades tradicionales de RDBMS.

⚡ Velocidad

Tiempo Real
Ingesta y procesamiento de datos en streaming, miles de operaciones por segundo.

🔄 Variedad

Datos Heterogéneos
JSON, XML, imágenes, videos, logs, sensores IoT - estructuras diversas.

✅ Veracidad

Calidad Variable
Tolerancia a datos incompletos o inconsistentes temporalmente.

Impacto en el Rendimiento

Ejemplo: E-commerce con 10M de productos RDBMS: - JOIN entre 5 tablas para mostrar producto - Índices múltiples, fragmentación - Escalado vertical costoso NoSQL (Documental): - Un documento = toda la info del producto - Sin JOINs, acceso directo - Sharding automático por región

🔒ACID en NoSQL

Propiedades ACID Tradicionales

⚛️ Atomicidad

Una transacción se ejecuta completamente o no se ejecuta en absoluto.

🔄 Consistencia

Los datos deben cumplir todas las reglas de integridad definidas.

🔒 Aislamiento

Las transacciones concurrentes no deben interferir entre sí.

💾 Durabilidad

Una vez confirmada, la transacción persiste permanentemente.

BASE: Alternativa NoSQL

BASE = Basically Available, Soft state, Eventual consistency

ACID BASE Implicación
Consistencia Fuerte Consistencia Eventual Los datos pueden estar temporalmente inconsistentes
Aislamiento Completo Disponibilidad Básica El sistema sigue funcionando aunque algunos nodos fallen
Estado Duro Estado Suave Los datos pueden cambiar sin entrada externa (reconciliación)

⚠️ Importante

Algunas bases NoSQL modernas ofrecen ACID configurable:

  • MongoDB: Transacciones ACID desde v4.0
  • Amazon DynamoDB: Transacciones ACID
  • Google Spanner: ACID global

🏢Casos de Uso Reales

🛒 E-commerce: Amazon

DynamoDB para carrito de compras, catálogo de productos, recomendaciones. Escalabilidad global, baja latencia.

📱 Redes Sociales: Facebook

Cassandra para timeline, mensajes. Neo4j para grafo social, sugerencias de amistad.

🎬 Streaming: Netflix

MongoDB para metadatos de contenido. Redis para cache de sesiones y recomendaciones en tiempo real.

🚗 IoT: Tesla

Time Series DB para telemetría de vehículos. Millones de puntos de datos por segundo de toda la flota.

Ejemplo Práctico: Sistema de Recomendaciones

Arquitectura Políglota: 1. PostgreSQL: Datos de usuarios, transacciones (ACID crítico) 2. MongoDB: Catálogo de productos, reviews (flexibilidad) 3. Neo4j: Relaciones usuario-producto, grafos sociales 4. Redis: Cache de recomendaciones, sesiones activas 5. Elasticsearch: Búsqueda de productos, análisis de texto Cada tecnología optimizada para su función específica.

🐳Docker: Containerización para NoSQL

¿Qué es Docker?

Docker es una plataforma de containerización que permite empaquetar aplicaciones y sus dependencias en contenedores ligeros y portables. Para nuestro curso, Docker será fundamental para:

🔧 Configuración Rápida

Instalar y configurar múltiples bases de datos NoSQL en minutos, sin conflictos de versiones.

🌐 Portabilidad

El mismo ambiente funciona en Windows, macOS y Linux. "Funciona en mi máquina" ya no es problema.

🔒 Aislamiento

Cada base de datos corre en su propio contenedor, evitando conflictos entre tecnologías.

📦 Reproducibilidad

Todos los estudiantes tendrán exactamente el mismo ambiente de desarrollo.

Conceptos Fundamentales

Concepto Definición Analogía
Imagen Template inmutable que contiene una aplicación y sus dependencias Como un molde para hacer galletas
Contenedor Instancia ejecutable de una imagen La galleta hecha con el molde
Dockerfile Archivo de texto con instrucciones para crear una imagen La receta para hacer el molde
Docker Compose Herramienta para definir aplicaciones multi-contenedor Orquestador de una banda musical

Comandos Esenciales de Docker

# === GESTIÓN DE IMÁGENES === docker images # Listar imágenes locales docker pull mongo:7.0 # Descargar imagen de MongoDB docker rmi imagen_id # Eliminar imagen # === GESTIÓN DE CONTENEDORES === docker ps # Listar contenedores activos docker ps -a # Listar todos los contenedores docker run -d --name mi-mongo -p 27017:27017 mongo:7.0 # Crear y ejecutar contenedor docker stop mi-mongo # Detener contenedor docker start mi-mongo # Iniciar contenedor docker restart mi-mongo # Reiniciar contenedor docker rm mi-mongo # Eliminar contenedor # === INTERACCIÓN CON CONTENEDORES === docker exec -it mi-mongo bash # Acceder al shell del contenedor docker logs mi-mongo # Ver logs del contenedor docker inspect mi-mongo # Información detallada del contenedor # === DOCKER COMPOSE === docker-compose up -d # Levantar servicios en background docker-compose down # Detener y eliminar servicios docker-compose logs # Ver logs de todos los servicios docker-compose ps # Estado de servicios

Ventajas de Docker

⚡ Velocidad

Los contenedores se inician en segundos, no minutos como las VMs. Ideal para desarrollo y testing.

📦 Portabilidad

"Build once, run anywhere". El mismo contenedor funciona en desarrollo, testing y producción.

🔧 Consistencia

Elimina el problema "funciona en mi máquina". Todos tienen el mismo ambiente.

📈 Escalabilidad

Fácil escalar horizontalmente creando más instancias del mismo contenedor.

💰 Eficiencia

Menor uso de recursos que las VMs. Más aplicaciones en el mismo hardware.

🔄 DevOps

Facilita CI/CD, microservicios y arquitecturas distribuidas modernas.

Desventajas de Docker

📚 Curva de Aprendizaje

Requiere aprender nuevos conceptos: imágenes, contenedores, volúmenes, redes.

🔒 Seguridad

Contenedores comparten el kernel del host. Requiere configuración cuidadosa.

💾 Persistencia

Los datos se pierden al eliminar contenedores. Necesita configurar volúmenes.

🐧 Dependencia del SO

En Windows/Mac requiere virtualización. Performance nativa solo en Linux.

🔧 Complejidad Operacional

Monitoreo, logging y debugging pueden ser más complejos que aplicaciones tradicionales.

📊 Overhead

Para aplicaciones simples, puede ser excesivo. No siempre es la mejor solución.
